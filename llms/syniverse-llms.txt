# Syniverse

> Syniverse is a US-headquartered wholesale telecommunications company with two very
> different halves. Its mobility business — inter-carrier roaming, IPX network and
> signaling, 5G SEPP, clearing and settlement, global SIM and satellite roaming — is
> carrier-facing, sales-led, and exposes no public API. Its messaging business is an
> A2P/CPaaS aggregator selling SMS, MMS, RCS, WhatsApp, social, push, voice, 10DLC
> campaign registration, messaging trust/anti-spam and mobile identity services, and it
> is published through a genuine self-serve developer portal — the Syniverse Developer
> Community (SDC) — with a free API key, a public US test channel and eleven
> downloadable OpenAPI/Swagger definitions. On network APIs Syniverse is a channel, not
> a source: it joined GSMA Open Gateway in April 2025 as a channel partner and announced
> an Aduna integration in June 2025, but no CAMARA-defined API is documented or callable
> on its developer portal today.

## What is NOT here

- No MCP server — nothing hosted, remote or local, in the docs, the GitHub org or any registry.
- No GraphQL and no gRPC surface.
- No public Postman workspace or collection.
- No AsyncAPI document; Event Manager is a RAML console only.
- No `/.well-known/` documents at all — no security.txt, no OIDC discovery, no oauth-authorization-server, no api-catalog, on any host.
- No public status page (`status.syniverse.com` does not resolve), no published SLA, no deprecation or sunset policy.
- No dated changelog or release notes.
- No published SOC 2 / ISO 27001 / PCI DSS certification and no trust center.
- No idempotency key anywhere in the estate.
- No CAMARA API, despite GSMA Open Gateway channel-partner membership.

## Notes for agents

- Auth is `Authorization: Bearer {SDC application access token}` almost everywhere. Messaging Trust is the exception — OAuth 2.0 client_credentials against `https://api.mt1.messaging-trust.syniverse.com/oauth2/token`.
- The first token an application is issued expires after 1 hour; once regenerated it does not expire.
- `POST` performs a **partial** update and `PUT` requires the **complete** entity. `PATCH` is not supported. This is the inverse of the usual REST convention.
- There is no idempotency key: retrying a write can duplicate a message, a passcode or a spam report. Carry your own `external_id`.
- Errors are `error_code` / `error_description`, not RFC 9457 problem details.
- `200` on a send is acceptance, not delivery. Real outcomes arrive on the Event Manager stream as `message_state_change` events with numeric failure codes.
- Two published definitions declare hosts you cannot reach anonymously: `api.mt1.messaging-trust.syniverse.com` does not resolve, and RPV/ATO publish only a sandbox host.
